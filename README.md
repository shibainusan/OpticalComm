# OpticalComm

2台のAndroid端末間で、**カメラのライト(トーチ)の点滅**で文字を送り、**カメラで点滅を読み取って**受信するアプリです。
ネットワークも Bluetooth も使わず、光だけで通信します。

- 言語/UI: Kotlin + Jetpack Compose、受信は CameraX
- パッケージ: `net.denpa.opticalcomm`(minSdk 26 / targetSdk 35)
- 1つのアプリに送信欄(上)と受信欄(下)が1画面にあり、両方の端末に同じ APK を入れます

## 使い方

1. 両方の端末にアプリを入れ、カメラ権限を許可します。
2. 受信側: アプリを開くと、画面下半分の受信欄にカメラのプレビューが映ります。
3. 送信側: 画面上部の送信欄に文字を入力します(UTF-8 で最大64バイト。日本語は1文字3バイト)。
4. 送信側の**背面ライト**を、受信側のカメラに 10〜30cm ほどで向けて「送信」を押します。
5. 受信側の「受信メッセージ」に文字列が出ます。

### うまく受信するコツ

- 受信側のカメラは、部屋の照明など**常に明るいものではなく、送信側のライトに向けて**ください。
- 部屋は暗めのほうが、ライトの明滅による輝度変化が大きくなり安定します。
- 受信欄のグラフ(青線=輝度、赤線=しきい値)が、ライトを当てる/外すで上下に振れるか確認できます。
- 受信側で背面カメラが使いにくい配置のときは「前面カメラ」に切り替えられます。
- 送信側と受信側は、**同じバージョンのアプリ**にしてください(ビット長やフレーム形式が違うと受信できません)。

## 受信画面の見方

「受信ビット」欄に、受信中のビットがリアルタイムに流れます。

```
10101010 10101010 01111110 ←プリアンブル受信成功
0x02 0x48 0x69 0xB7 ←CRC OK
```

- 同期待ち(HUNT)の間は、直近40ビットが常に最後の行で流れ続けます。同期用パターンを検出するまで、同じ行が更新されます。
- `←プリアンブル受信成功` : 同期用パターンを検出した時点で、その行が確定します。同期前は失敗の行を出さず、更新を続けます。
- プリアンブル以降は、8ビットごとに `0x..` の HEX 表示になります(先頭から LEN、本文、CRC8)。
- `←CRC OK` / `←NG(len=…, CRC不一致)` / `←失敗(長さ不正…)` : 受信結果
- CRC が合わなくても LEN 分は受信を続け、化けた文字列も「受信(エラー): …」として表示します。LEN が不正(64超)の場合だけ中止します。

## 通信方式

- **変調**: OOK(ライト点灯=1 / 消灯=0)、1ビット `BIT_MS` = 70ms(約14bps)。
- **フレーム**:

  ```
  AA AA 7E | LEN | PAYLOAD (UTF-8) | CRC8
  ```

  - 先頭の `AA AA 7E`(10101010 10101010 01111110)がプリアンブル+同期パターンです。受信側は末尾の `AA 7E`(16ビット)で同期します。
  - 各バイトは MSB first です。
  - `CRC8` は多項式 0x07 で、LEN と本文が対象です。
  - 送信開始前に約1秒の消灯を入れ、受信側のしきい値校正に使います。

## 受信の仕組み

```
LightReceiver (CameraX 30fps, AE/AWB ロック)
  → フレーム全体の平均輝度
  → SignalSlicer (適応しきい値 + エッジ時刻の補間 + ビット中央サンプリング)
  → BitStreamDecoder (プリアンブル検出 → LEN/本文/CRC)
  → 画面表示
```

- 時刻はカメラのフレームタイムスタンプで管理します。フレーム数ではなく、輝度がしきい値を横切る時刻をフレーム間で線形補間してエッジ位置を求めるため、1ビットが約2フレームでも読み取れます。
- 輝度は上位ピクセルではなく画面全体の平均を使います。白飛びした照明が常に最大値になって点滅が見えなくなる問題を避けるためです。

## ビルド

Android Studio で開くのが簡単です。コマンドラインでは JDK 17 以上(Android Studio 付属の JDK でも可)が必要です。

```bash
./gradlew test           # JVM 単体テスト(プロトコル、スライサ)
./gradlew assembleDebug  # デバッグ APK
```

PowerShell で JDK が見つからない場合は `JAVA_HOME` を設定してください。

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat test assembleDebug
```

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `Protocol.kt` | `BIT_MS` などの定数、`Frame.encode`、`BitStreamDecoder`、CRC8 |
| `SignalSlicer.kt` | 輝度波形 → ビット列(しきい値、エッジ補間、再同期) |
| `TorchSender.kt` | トーチ点滅による送信(絶対時刻でドリフトを防止) |
| `LightReceiver.kt` | CameraX による輝度取得 |
| `CommViewModels.kt` | 送信/受信の状態管理、受信ログの整形 |
| `ui/MainScreen.kt` | Compose の画面 |

## 速度について

`BIT_MS`(`Protocol.kt`)で調整できます。送信側と受信側で必ず同じ値にしてください。

- 30fps のカメラでは、70ms が実用上ほぼ下限です(1ビット約2フレーム)。
- 60fps に対応した端末なら、`LightReceiver` の FPS 設定を上げることでさらに短縮できる可能性があります。
- 端末のトーチ応答に遅れやばらつきがあると、短くするほど取りこぼしが増えます。
